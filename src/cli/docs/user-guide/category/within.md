# 范畴内：装载与分析

数学在这套工具里，帮我们得到的是一条确定的边界：哪些是验过没问题的（骨架自洽）、哪些是确定做不到的（接不上）、哪些是还没做的（规则空白）。

它不产出业务结论，但它让“确定”“不可能”“待定”三件事不再含糊。把“我没做”“查不了”“不可能”三件事分得清清楚楚。 

没有它，这三样混成一团，业务方就会把“没做”当成“再努力就行”，或者把“不可能”当成“补个规则就能出”。

报告里的 0 数学说的是 业务含义
结构公理 0 这两条关系的种类不发这类规矩 不是没配，是这类关系本来就不带层级
领域公理 0 你没写业务规则 是空白，等你填
派生关系 0 结构上接不上，不是缺规则 是“不可能”，补配置也没用

这三个词都出现在范畴内分析的报告里，各自对应一类「0 或几条」。用实习能懂的话讲，每个都回答一个问题：是什么 → 谁来发 → 报告里为什么是 0。

结构公理

一句话：管「层级」的规矩——谁是谁的子类、谁包含谁。

是什么：如果本体里有「内容是一种素材」「账号属于某个组织」这种层级关系，结构公理就是管这类层级不能乱的规矩。比如：

· 子类必须继承父类的关系
· 分类不能自己包含自己（循环）
· 包含关系要能传递（A 包含 B，B 包含 C，则 A 包含 C）

谁来发：工具的目录（catalog）按关系种类自动发。但只对四类规范关系发——Subsumption（子类）、Parthood（部分）、Causation（因果）、Opposition（对立）。

报告里为什么是 0：示例里的两条关系是 PublishedOn（发布在）和 UsesMaterial（使用素材），都不属于那四类。所以目录一条都不发。不是「没配」，是这两条关系本来就不带层级。

业务含义：模型里没有「内容分类」「账号层级」这类结构，系统不会自动做分类继承。
想要层级 → 得新增 Subsumption 这类关系，不是给现有两条补配置。

领域公理

一句话：管「业务规则」的规矩——你所在领域的约束。

是什么：本体自己声明的业务规则。比如：

· 内容必须发布在至少一个账号上（基数约束）
· 一个内容只能发在一个账号上（唯一性）
· 账号停用后内容不能发布（条件约束）
· 某类内容必须用某类素材（互斥 / 搭配）

谁来发：本体自己——写在本体的 axioms: 子句里。工具不替你发明，它只校验你声明的。

报告里为什么是 0：示例本体没有写 axioms: 子句。这是真正的空白——不是「不该有」，是「你没写」。

业务含义：系统不会自动校验业务合规。上面那些规则目前都不存在。
想要业务约束 → 在 axioms: 里写上去，写了就会被校验。

派生关系

一句话：不是明说的，是复合出来的新关系。

是什么：两条关系首尾相接，串起来得到第三条。比如：

```
内容 → 账号
账号 → 组织
```

两条接得上（前一条的终点「账号」= 后一条的起点「账号」），复合出：

```
内容 → 组织（派生）
```

这条没在规格里声明过，是算出来的，所以叫派生关系。

谁来发：工具自己算——遍历所有关系对，f.to == g.from 就复合，复合结果不在已有关系里、也不在派生列表里的，记一条派生。

报告里为什么是 0：示例两条关系是

```
内容 → 账号
内容 → 素材
```

起点都是内容，终点不同，前一条的终点（账号）不是后一条的起点（素材），接不上。复合这条路根本走不通，所以派生 0 条。

业务含义：系统只知道你明确声明的关系，不会自动推出新关系。
想要派生 → 得补能接上的关系（比如加上「账号 → 组织」），不是补配置。

三者的关键区别

 结构公理 领域公理 派生关系
管什么 层级 业务规则 复合出的新关系
谁来发 目录按关系种类发 本体自己声明 工具自己算
报告里 0 的原因 关系种类不属那四类 没写 axioms: 两条关系接不上
是「没做」还是「不可能」 不是没配，是种类不带 没做，等你写 不可能，结构上接不上
想要怎么补 新增 Subsumption 等关系 写 axioms: 补能接上的关系

一句话记法

· 结构公理：层级规矩。示例里是 0，因为关系种类不带层级——不是没配。
· 领域公理：业务规矩。示例里是 0，因为你没写——是空白。
· 派生关系：复合出的新关系。示例里是 0，因为两条关系接不上——是不可能，补配置也没用。

三者刚好演示了三种不同的 0：不该有 / 还没做 / 不可能。这也是为什么报告要把它们分开列——分开才能分清「没做」和「做不到」。
