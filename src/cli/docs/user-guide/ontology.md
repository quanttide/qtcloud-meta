# 本体的使用过程

本体及关系的数据源主要是规格：类、属性与关系从规格文档里来，不从任意文本里现抽。命令行只提供本体录入格式——按格式填好的录入件交进命令行，由它接收、校验、入库；命令行不提供 LLM，抽取与整理发生在进入命令行之前。流程的全局结构见[用户指南](index.md)，链路各阶段的行为与完整示例见主文档[用户指南](../../../../docs/user-guide/index.md)的「本体写入的过程」。

## 过程

1. 准备规格：从规格文档取出这次要录入的本体及关系，理清类、属性、归属与引用。
2. 按录入格式填写：每类条目各归其位，引用的类与属性必须是本体里已有的；这一步靠人与上游工具，命令行不代劳。
3. 录入：命令行按格式接收，做结构校验——`domain` / `range` 对不对、新增是否破坏现有定义，SHACL 与一致性检查在这一步跑。
4. 打开审批页面处理请求：批准、拒绝或修正后批准，修正内容记入 `human_edit`。
5. 批准生效：写入 Turtle/OWL 本体文件，本体版本加一；拒绝则丢弃或退回修改。

> 命令尚未设计，上面是流程定义，供后续实现对照。

## 为什么数据源是规格

规格是已经被人审过一遍的正式产物，里面的类与关系有出处、有版本；从任意文本里抽出来的东西没有这两样。命令行不提供 LLM，等于把「猜」这一步挡在入口之外——进来的每一条本体及关系都能追到一份规格。
