# 用户指南

本文讲 qtcloud-meta CLI 的日常使用：怎么构建、怎么跑，以及本体写入这条流程在命令行上怎么走。命令清单见 [API 参考](../api-references/index.md)，流程的行为定义见主文档的[用户指南](../../../../docs/user-guide/index.md)。

## 构建与运行

CLI 是 Rust 工程，在 `src/cli` 下用 Cargo 构建：

```bash
cd src/cli
cargo build
cargo run
```

当前 `cargo run` 输出一行 `qtcloud-meta` 后退出。两条流程所需的本地环境（SQLite、Ollama 等）按主文档技术栈准备，清单见[开发指南](../dev-guide/index.md)。

## 本体写入的使用过程

这条流程的命令尚未设计，下面是主文档定义的过程，供后续实现对照：

1. 准备输入：把文档、对话记录或网页文本放到本地。
2. 触发抽取：由 CLI 走完 LLM 抽取、本体对齐、SHACL 校验与变更生成，产出待审批的本体变更。
3. 打开审批页面处理请求：批准、拒绝或修正后批准。
4. 批准生效：新概念写入 Turtle/OWL 本体文件，后续抽取与分析即可复用。

链路各阶段的行为与完整示例见主文档[用户指南](../../../../docs/user-guide/index.md)的「本体写入的过程」。

## 范畴分析的使用过程

这条流程在命令行上暂无命令设计，下面是主文档定义的过程，供后续实现对照：

1. 提交分析任务与所处范畴。
2. 查 `category_mapping` 做映射翻译，查 `conflict` 检查既往裁决。
3. 映射缺失时生成 `change_request` 等人类确认，分析暂停在当前范畴。
4. 输出目标范畴下的整合结论。

冲突处理规则与走查示例见主文档用户指南的「范畴分析的过程」。

> 命令尚未实现，CLI 当前处于骨架阶段：此前两版命令设计（七个命令、单个 `change submit`）都已删除，现在没有任何命令设计。上文是方案定义的使用过程，命令落地后在此补充具体用法。
