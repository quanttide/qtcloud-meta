# 范畴的使用过程

本体及关系录入系统之后，范畴的性质分析遵循一定的规则，不是 LLM 猜测。规则只有三样：范畴的本体承诺声明它认哪些实体、属性与关系，`category_mapping` 声明怎么从一个范畴翻到另一个，`conflict` 声明哪些分歧已由人裁决——分析只在这三样既定规则上走。流程的全局结构见[用户指南](index.md)，三张表的结构见主文档[开发指南](../../../../docs/dev-guide/index.md)。

## 过程

1. 选定范畴：确定当前范畴，读出它的本体承诺。
2. 映射翻译：查 `category_mapping` 取函子规则，按规则把断言翻到目标范畴，不临时发挥。
3. 冲突检查：查 `conflict` 比对既往裁决，命中 `true_conflict` 的按既往裁决处理。
4. 规则缺失：不猜，生成一条 `change_request` 等人类定义规则，分析暂停在当前范畴。
5. 输出结论：给出目标范畴下的整合结论，回传元智能体。

> 命令尚未设计，上面是流程定义，供后续实现对照。

## 为什么按规则而不靠猜

翻译的每一步都要能追到一条具体规则——哪条函子、哪条裁决。追不到就停在第 4 步，宁可不给结论，也不让模型替规则做决定。LLM 猜出来的东西无法复算：同一个输入换个说法可能得到另一个结论，而规则跑一百遍都是同一个结论，出错时也才知道错在哪条规则上。
