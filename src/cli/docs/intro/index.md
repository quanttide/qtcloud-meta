# 为什么值得用 qtcloud-meta

AI 帮你写资料，写完就忘——每次对话都是重新开始，昨天定过的名字、写法，它不记得。可资料要长期放在一起：同一个东西在两篇文档里两个名字，同一个字段在两份表里两种写法。资料攒得越多，这种对不上的地方越多，回头想统一就越难。

qtcloud-meta 是**系统的元认知工具**：把「什么算一致」提前定下来，每次写完拿去照一遍，不一致当场指出来。它不是又一个 AI——规则全写死在程序里，不调模型，同一份资料跑一百次，结果一样。

「什么算一致」不靠现场发挥：范式、范畴、属性这些概念早就定义好了，每个概念都带着自己的检查规则——怎么算站得住、怎么算对得上、怎么算写对了。

## 它检查两件事

**概念对没对上。**本体里的对象、关系、公理过一遍结构检查；两个域之间的说法查翻译规则，翻不翻得通、缺哪条规则，报告里写明白。缺规则不算错误——报告会指出该补哪个文件。

**字段写没写对。**每张表的字段该怎么写有标准：叫什么名、什么类型、什么格式。一条命令逐个字段核，哪写错了、哪还没进标准，一条条列出来。拿它检查我们自己的表，一次找出 39 处对不上。

## 用户画像

- **用户**：研发团队的 leader。
- **场景**：带领团队开发大型、复杂系统——多个域、多张表，还有 AI 参与写资料。
- **需求**：确保系统的一致性和可认知，符合人类的概念——概念对得上、写法统一，人和 AI 都能看懂系统在说什么。
- **功能**：qtcloud-meta 把「什么算一致」立成概念体系（范式、范畴、属性……），每个概念带着机器可查的判法：结构过校验、跨域查翻译、字段对标准，不一致当场列出。规则写死、不调 AI，配进检查流程后谁跑结果都一样。

**记忆不连续，标准连续**——AI 会忘，标准不会。

## 怎么开始

```bash
cargo install qtcloud-meta-cli
qtcloud-meta property calibrate 你的表.yaml
```

三条命令的完整用法见[用户指南](../user-guide/index.md)。
