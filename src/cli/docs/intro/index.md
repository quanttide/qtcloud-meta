# 为什么值得用 qtcloud-meta

qtcloud-meta 是**系统的元认知工具**：帮助 AI 建立概念上的一致性。

写资料的是 AI，而 AI 没有连续的记忆——每次对话都是新起的一段，昨天写了什么、上次怎么定义的，都不在场。可写下的资料要长期共存：同一个东西在两篇文档里叫了两个名字，同一个字段在两份表里两种写法，两个域对同一个概念各说各话。这不是哪篇写得不好，是一群没有共同记忆的作者必然写出的结果。

光提醒 AI「注意一致性」没用——没有记忆就没有一致性可言。所以做法是反过来：先把「什么算一致」立起来，再让每次写作去对。

## 概念体系：什么算一致，先由我们定义

我们给系统定义了一套概念——**范式、范畴、属性、公理、映射、标准**——每个概念都带着自己的判法：怎么算站得住、怎么算对得上、怎么算合约定。这套概念是元工程的家底，判法写死在代码里，不调 LLM：同一份资料对同一套概念，跑一万次结果一样。

命令行只是入口。元认知落在概念体系上——命令做的事，是拿这套概念去照系统自己写下的资料，不一致就当场照出来。

## 范式照结构：概念体系自己站得住吗

```bash
qtcloud-meta paradigm within qtcloud-work-cli
qtcloud-meta paradigm between qtcloud-code-cli qtcloud-work-cli
```

本体作为对象和态射装进范式，公理逐条过数学校验；两个域之间查映射表翻译断言——实跑翻通 6 条：`ContractConfig → Artifact`、`CodeConfig → Criterion`……映射表是文件，补一处通一路，缺表停在 change_request 点名该补哪个文件。装载步注明本次读的是文件还是内置快照，出错能对账到具体一份表，不靠印象。

## 属性照字段：写下的东西合乎共同约定吗

```bash
qtcloud-meta property calibrate 你的表.yaml
```

属性是范畴名下的字段标准：九条字段各带机器可查的规则（类型、格式、正则、枚举），一条命令核到底——不合的在哪（带「文件::路径」，改文件），标准还没收的有哪些（补标准表）。这不是设想：拿它对自家范式表实跑，当场列出 39 处偏差。

## 记忆不连续，标准连续

AI 每次写完跑一遍，概念不一致当场现形，而不是等三天后下游报告歪了才有人发现。这也是它敢进检查脚本、敢写进 skill 当固定步骤的原因：不用信任作者的记忆，只用信任可以复跑的判法。

## 落到谁身上

- **改表的人**：改动的代价从隐形变当场——`--strict` 有失败退出码 1，配进检查脚本，改坏了当场红。
- **对接两个域的人**：翻译从「某个人脑子里」搬进仓库，谁来都一样。
- **写 skill 的人**：把校准命令放进 skill，agent 每次真跑，不凭记忆猜约定。

## 三行起步

```bash
cd src/cli && cargo build
./target/debug/qtcloud-meta paradigm within qtcloud-work-cli
./target/debug/qtcloud-meta property calibrate examples/property/standard.yaml
```
