# API 参考

本页三样东西：已实现的接口、命令的命名规则、以及唯一的命令设计。命令细节见[本体的 API](ontology.md)。怎么用看[用户指南](../user-guide/index.md)，工程结构看[开发指南](../dev-guide/index.md)，流程定义见主文档[用户指南](../../../../docs/user-guide/index.md)。

> 命名规则与命令为设计稿，尚未实现。骨架阶段唯一落地的是「已实现的接口」一节，命令的名字与参数随实现调整。

## 已实现的接口

包名 `qtcloud-meta-cli`，版本 0.1.0，edition 2024，当前无第三方依赖。命令名 `qtcloud-meta`，入口 `src/main.rs`，运行向标准输出打印一行 `qtcloud-meta` 后正常退出，无子命令。

## 命名规则

一级按名词域切，一级不放动作词：读者一句话就能复述——一级是对象，二级是对对象做的动作。当前只保留一个域 `change`（本体变更）。

二级共用一张动词表：`submit` 提交、`list` 列清单、`show` 看详情、`apply` 生效写入、`translate` 按映射翻译。新动作先查表再造词，词表外不造近义词。

不为一个查询单开一个域：`category`、`mapping`、`conflict` 这类只读查询本轮未保留，看队列与详情是审批页面的事，命令行只提交。

命令名取自用户嘴里的叫法——变更、范畴、映射、冲突，与 SQLite 表名重合只算实现细节的对应，不作命名依据。

参数分两层：全仓全局只留每条命令都消费的，其余挂在用它的子命令上；一个概念只留一套参数名。

## 命令

只有一个：`qtcloud-meta change submit <输入路径>`，提交一份非结构化输入，走完 LLM 抽取、本体对齐与 SHACL 校验，产出一条待审批的变更。链路到落库为止，生效与本体文件的写入在审批页面完成。参数与读写落点见[本体的 API](ontology.md)。

## 参数

全仓全局只有三个，因为每条命令都消费它们：`--db <路径>` 定位 SQLite 单文件（缺省 `meta.db`，环境变量 `QTCLOUD_META_DB`），`--json` 决定结果怎么输出，`--version` 打印版本号、与 `Cargo.toml` 一致。装载顺序写死：命令行 > 环境变量 > 缺省规矩。

域参数与子命令参数不进全局，各自挂在用它的命令上，清单见[本体的 API](ontology.md)。

## 输出与退出码

标准输出只放结果与 `--json` 的 JSON，提示、进度与错误一律走标准错误，管道里不会混进别的东西。

退出码 0 表示成功，1 表示失败（输入读不到、校验不通过、LLM 不可达、指定的范畴不存在）。「等待人类确认」是正常结果而非失败：`change submit` 产出待审批变更时仍退出 0，靠输出里的变更 id 与状态表达下一步。

## 设计取向

1. CLI 执行链路但不做裁决：链路止于 `change_request` 落库，人类确认留在审批页面，两边共享同一张队列表。
2. 命令行不碰本体文件：生效由审批侧写入 Turtle/OWL 文件，命令行只提交候选，本体变更因此可重放、可回滚、有版本号。
3. 状态只有两处：事实集中在 SQLite 单文件与 Turtle/OWL 文件，命令行只负责 SQLite 这一侧，不引入第三份状态。
4. 输出面向元智能体：`--json` 的字段是脚本契约，只加不改。
5. 命名先定轴再起名：一级名词域、二级共用动词表、全局参数按「每条命令都消费」准入。三条来自报告仓 `data/report/retrospective/cli-naming.md`，本页是它落地后的命令面。
